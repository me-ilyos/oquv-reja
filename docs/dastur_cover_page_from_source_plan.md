# Rebuild the O'quv Dastur cover page from the reference source .docx

## Context

Teachers report the generated O'quv Dastur DOCX doesn't match the required look — most visibly, the cover page's layout comes out different from what's expected (see attached reference screenshot). Root-caused to `plans/dastur/build_template.py`, which currently builds the cover page from scratch with python-docx (`_build_cover_page_title`, `_build_cover_page_major_and_signoff`, lines 127–187) and has drifted from the real reference document (`sources/Kiberxavfsizlik_asoslari_fan_dasturi_ATDT.docx`) in several concrete ways, confirmed by direct XML inspection of both files:

- **Approval box ("TASDIQLAYMAN") column widths** are off by ~324 twips (`[5495, 4081]` in the generator vs `[5495, 4405]` in the reference).
- **Approval box internal alignment is lost**: the reference has 8 separate paragraphs (5 centered, 2 right-aligned); the generator writes it as one run with `\n` line breaks, rendering the whole box uniformly left-aligned.
- **~9 fewer blank spacer paragraphs** before the main content table than the reference (2 vs ~11), which pushes the 98-row main table up so it encroaches onto page 1 instead of starting cleanly on page 2 — this is very likely what reads as tables "shrinking" on the title page.
- **Page size mismatch**: generator forces A4; the reference is US Letter.

## Decision

Rather than hand-tune the python-docx generator to match, **use `sources/Kiberxavfsizlik_asoslari_fan_dasturi_ATDT.docx` directly as the source of the cover page** — load it, keep its layout/formatting byte-for-byte, and only substitute the specific runs that need to become per-course Jinja tags. This guarantees pixel fidelity to the reference since it *is* that document, not a recreation of it.

**Known trade-off, accepted for this change:** this reference file is a Google Docs export (`docProps/core.xml` → `creator="Un-named"`), the same origin `docs/dastur_template_rebuild_plan.md` moved away from (that rebuild switched to A4 + explicit Times New Roman + a maintained python-docx builder, specifically to fix Letter-size pages and inconsistent font application). Adopting the reference file here means the cover page reverts to **Letter page size**, and cover-page runs keep whatever direct formatting the export gave them rather than uniformly inheriting from a clean style. This doc supersedes that earlier rebuild's decision for the cover page only — Table 1/Table 2 (built by `build_template.py` from `table1_spec.py`/`table2_spec.py`) keep the A4-era clean-formatting approach untouched.

**Scope: cover page only.** Table 1 (58 rows) and Table 2 (17 rows) are untouched by this change; they continue to be generated as before and appended after the cover page.

## Approach

Replace `_build_cover_page()` in `plans/dastur/build_template.py` with logic that loads the reference `.docx`, trims it down to just the cover page, and tags the dynamic runs — instead of constructing the cover page from paragraph/run calls.

### 1. `plans/dastur/build_template.py`

- **Remove**: `_build_cover_page`, `_build_cover_page_title`, `_build_cover_page_major_and_signoff`, `_build_approval_table`, `_add_run_paragraph`, `_add_bold_line`, and the `TABLE0_COL_WIDTHS` constant — all dead once the cover page comes from the source file. Drop the now-unused `CellSpec`/`RowSpec`/`TASDIQLAYMAN_BOX` imports that only fed those functions.
- **Remove**: the `_set_page_setup()` call from `build()` (and the function itself) — page size now comes from the loaded source document's `sectPr` (Letter). Drop the now-unused `Cm`/`Mm` imports.
- **Trim `_register_styles`**: keep the `Normal` style font-forcing (Times New Roman, Pt(14), line_spacing 1.0 — this still benefits Table 1/Table 2 runs generated by existing code, and helps any cover-page runs lacking explicit `rFonts`) and keep `DasturJustify` (still used by `_build_footer_table`'s `IZOH` paragraph). Drop `DasturCentered`, `DasturHeading`, `DasturItalic` — confirmed unused outside the removed cover-page functions.
- **Add** `SOURCE_TEMPLATE_PATH` pointing at `sources/Kiberxavfsizlik_asoslari_fan_dasturi_ATDT.docx`.
- **Add** `_load_cover_page(path: Path) -> Document`: open the source file with `Document(path)`, then truncate its body — find the first `<w:tbl>` with more than 5 rows (the 98-row main table; the approval box is a 1-row table so this distinguishes them), and remove every body element from that table onward, up to but excluding the trailing `<w:sectPr>` (must be preserved — it carries the page setup). Verified structure by dumping the source's body element sequence: index 0–34 are cover-page paragraphs + the 1-row approval-box table at index 2, index 35 is the 98-row main table where truncation should happen (11 blank paragraphs, indices 24–34, sit right before it).
- **Add** `_replace_run_text(paragraph, old, new)`: finds the single run containing `old` as a substring and replaces it in place, preserving that run's formatting; raises if `old` isn't found in any single run (never silently ship a template with a literal label instead of a working tag).
- **Add** `_consolidate_tag(paragraph, start_marker, end_marker, tag)`: for the one case where Word's autocorrect split a value across several runs (the "Ta'lim yo'nalishi" value spans 6 separate runs), puts the tag whole into the first matching run and blanks out the rest, so the tag still lives in exactly one non-empty run (required — docxtpl's tag parser breaks if a tag is split across runs).
- **Add** `_insert_cover_page_tags(document)`: walks the cover-page paragraphs and applies the above helpers to swap in Jinja tags, confirmed against the source's actual run structure (paragraph indices and exact run splits captured during investigation):
  - `"KIBERXAVFSIZLIK ASOSLARI"` (single run) → `"{{ course.name|upper }}"`
  - `"kunduzgi"` inside the `"(kunduzgi ta'lim uchun)"` run → `"{{ education_form }}"`
  - `"600000 – Axborot-kommunikatsiya texnologiyalari"` (Bilim sohasi value run) → `"{{ major.bilim_sohasi }}"`
  - `"610000 – Axborot-kommunikatsiya texnologiyalari"` (Ta'lim sohasi value run) → `"{{ major.talim_sohasi }}"`
  - `"60610800 – Axborot texnologiyalarining dasturiy ta'minoti"` (Ta'lim yo'nalishi value, spans runs — needs `_consolidate_tag`) → `"{{ major.talim_yonalishi }}"`
  - `"2026"` in `"Namangan – 2026"` → `"{{ year }}"`
  - Within the "Mazkur o'quv dasturi ..." paragraph (all substitutions land in the same single run): `"Turan International University"` → `"{{ university }}"`, `"Filologiya"` → `"{{ kafedra }}"`, `"2026-yil"` → `"{{ kafedra_council.year }}-yil"`, the 19-underscore blank → `"{{ kafedra_council.date }}"`.
  - Leave the approval box (TASDIQLAYMAN block) and "Tuzuvchi:"/"Taqrizchilar:" lines untouched/static (blank fill-ins) — matches current behavior; `kontekst.py` has no author/reviewer fields.
- **Update `build()`** to: `document = _load_cover_page(SOURCE_TEMPLATE_PATH)` → `_register_styles(document)` → `_insert_cover_page_tags(document)` → then the existing, unchanged `build_table_from_spec(...)`, `_build_footer_table(...)`, `_add_trailing_paragraphs(...)`, `_build_footer(...)` calls (these already append correctly onto a non-empty `Document` since `add_table`/`add_paragraph` append to the end of body regardless of prior content).
- Keep `_check_template_variables` / `EXPECTED_TOP_LEVEL_VARS` as-is — still validates the full tag set including the new cover-page tags. Confirmed during prototyping that this self-check passes with the new cover page.
- The source document has no existing footer part, so `_build_footer`'s page-number injection into `document.sections[0].footer` still applies cleanly with no leftover footer content to conflict with.
